# NSS 课程实验平台 · 产品优化方案

日期：2026-06-17
作者视角：产品 + 技术
状态：待用户评审（已按"鼓励用AI + 轻量步骤完成度"校准）

## 一、产品初心（最终校准）

> 我们是 AI 教学平台，**鼓励学生用 AI 生成代码**——这是高效的学习方式。
> 但学生不能当"甩手掌柜"：不能一句"帮我做完实验"就交差。
> 必须让学生**逐步走完每个引导步骤、确认看过实验的每个细节**。
>
> 防伪的真正目的 = **证明学生真的在我们平台上、跟着引导、一步步推进过实验。**

关键词是 **过程（process）** 与 **逐步推进（step-by-step）**，不是"防止用 AI"，也不是"防篡改结果"。

## 二、现状诊断

### 当前能力
- ✅ 防篡改：HMAC 签名，学生改不了服务器记录
- ✅ 三步流程：init / report / submit
- ✅ 教师面板：徽章、状态筛选、验证按钮
- ✅ 软删除、重做留痕

### 核心短板
**当前系统只签"最终结果"，完全不记录"是否逐步走过引导"。**

要拒绝的场景（甩手掌柜）：
> 学生不看引导、直接让 AI 一次性产出全部答案 → 立刻 submit → 签名有效 ✅
> 系统无法区分"逐步推进完成"和"一句话甩给 AI 做完"。

定位差距：
- 现在做到的是 **防篡改（tamper-evidence）**：证明"交上来之后没改过"
- 初心需要的是 **证明逐步推进（proof-of-progress）**：证明"是跟着引导一步步走完的"

## 三、解法：把"引导"做成可记录的步骤轨迹

把证据包从「report.md + 文件哈希」扩展为「**逐步推进轨迹**」，并对轨迹整体签名。

### 过程证据三要素（轻量版）

1. **引导步骤完成度（guidance progress）— 核心**
   - 每个实验定义若干引导步骤（如：理解目标 → 看原理 → 生成代码 → 运行验证 → 总结）
   - 学生在 nsscli 里**逐个推进**，每完成一步记录一条轨迹（步骤ID + 时间戳）
   - 不强制问答（保持轻量、不打扰），只记"是否逐步走过"
   - 信号：认真学习会逐步走完 6/6；甩手掌柜是 0/6 直接交

2. **时间节奏（time rhythm）**
   - 每个关键事件的服务器时间戳（report 开始、各步完成、submit）
   - 信号：3 小时的实验 2 分钟走完全部步骤 = 高度可疑
   - 落点：复用现有 `timeline` 字段（目前空置）

3. **平台交互存在性（platform presence）**
   - 证明学生确实在 nsscli 平台内操作过（步骤推进本身就是证据）
   - 信号：完全没有平台内步骤轨迹 = 没在平台做

### 明确不采集（与定位冲突，删除）
- ❌ "代码是否逐步手写"——用 AI 生成本就一次成型，正常，不作为可疑信号
- ❌ "对话轮次/深度"——本期不做强制问答，不以此判断
- ❌ 实时监控/录屏——过重、侵犯隐私

### 签名升级
`evidence_hash` 的输入从 `{report, files}` 扩展为 `{report, files, timeline, guidance_progress}`。整包签名，过程数据被改即检出。

## 四、引导步骤怎么定义

实验 manifest（`src/labs/manifest.json`）为每个实验增加 `steps` 字段：
```json
{
  "exerciseID": "01-crypto-basic",
  "steps": [
    { "id": "goal", "title": "理解实验目标" },
    { "id": "principle", "title": "了解加密原理" },
    { "id": "implement", "title": "用 AI 生成实现代码" },
    { "id": "run", "title": "运行并验证结果" },
    { "id": "summary", "title": "总结实验要点" }
  ]
}
```
学生在 nsscli 内推进每一步，nsscli 记录 `guidance_progress`，submit 时随证据上传签名。

## 五、教师端：从"看签名"到"看推进画像"

教师面板每个提交展示：
- 引导步骤完成度（如 5/6，可视化进度条）
- 耗时（vs 实验预期耗时）
- 各步完成时间线
- **风险提示**：步骤完成度低 + 耗时极短 → 🔴 疑似甩手掌柜

教师看到的不再是 `✅签名有效`，而是「这个学生走完全部 6 步、花了 1.5 小时」vs「这个学生 0 步、2 分钟交卷」——一目了然。

## 六、风险信号引擎（自动初筛，辅助不判罚）

后端对每个提交计算 `progress_score`：
- 🟢 真实：步骤完整 + 耗时合理
- 🟡 存疑：部分步骤缺失
- 🔴 高危：步骤完成度极低 + 耗时极短 → 疑似甩手掌柜

仅辅助教师初筛，**不做自动判罚**（避免误伤），最终判断权在教师。

## 七、隐私与诚信边界
- 只记步骤ID + 时间戳，不记录学习内容原文，隐私友好
- 明确告知学生"平台会记录实验推进过程用于诚信核验"，透明优先

## 八、实施优先级

### P0（本期，逐步推进最小闭环）
1. manifest 增加实验 steps 定义
2. nsscli 实验流程支持逐步推进 + 记录 `guidance_progress`
3. submit 时上传 progress + timeline 并纳入签名
4. 教师面板展示步骤完成度 + 耗时

### P1（下一期）
5. 风险评分引擎 + 🟢🟡🔴 标签
6.（可选）submit 前一次综合理解问答（用户当前选择不做，留作未来增强）

### P2（打磨）
7. 身份验证加固（防冒名）
8. secret 加固（密钥管理、轮换）

## 九、不做（YAGNI / 边界外）
- 不做"防止用 AI 生成代码"（违背平台定位）
- 不做强制逐步问答（本期保持轻量）
- 不做实时监控/录屏
- 不做自动判罚（只初筛，教师决策）

## 十、一句话总结
我们鼓励学生用 AI，但要求"逐步走完引导、看过实验每个细节"。核心是把证据从**结果**扩展到**逐步推进轨迹**（引导步骤完成度 + 时间节奏），让"甩手掌柜"在过程维度暴露，同时完全不打扰认真用 AI 学习的学生。
